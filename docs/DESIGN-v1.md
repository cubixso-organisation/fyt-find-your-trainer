## Problem Statement
A client in skills / IT / corporate training needs one platform where trainers run batches,
students follow them from their phones, institute admins see what is happening, and corporate
buyers get proof of completion. It must serve both multi-trainer organizations and solo trainers
as tenants of a single SaaS.

## Demand Evidence
Client brief only. No users yet, no current-workflow data. The client's request is the only
evidence of demand. This is the largest risk in the plan (see The Assignment).

## Status Quo
Unknown. The builder has not yet seen how the client runs training today. Likely candidates
(unverified): WhatsApp groups + Google Drive/Sheets, Zoom/Meet + Google Classroom, or a
disliked LMS. The v1 must beat whichever it actually is.

## Target User & Narrowest Wedge
All four roles are in scope ("for all"). To keep that coherent, v1 is centered on the one
loop every role touches:

**Batch → Session → Material/Assignment → Submission → Progress → Certificate**

| Role | Surface | What they do in the loop |
|---|---|---|
| Student | Mobile (Expo) | See schedule, join session link, open materials, submit assignments, view progress, download certificate |
| Trainer | Mobile (Expo) + web | Create sessions, mark attendance, post materials/assignments, grade, message batch |
| Org admin / solo trainer back-office | Web (Next.js) | Manage courses, batches, trainers, students, enrollments; dashboards; issue certificates |
| Corporate buyer | Web (read-only) | See their employees' attendance, completion, scores; export reports |
| Platform super-admin | Web | Manage tenants, plans, support impersonation (audited) |

Wedge for the client pilot: one real batch runs end-to-end on the platform (enroll → 4+ sessions
→ 2+ assignments graded → certificate issued) with zero WhatsApp/Sheets fallback.

## Constraints
- Stack (decided): Expo / React Native (TypeScript), Next.js (App Router), Supabase
  (Postgres, Auth, Storage, RLS).
- Tenancy: both organizations (many trainers) and solo trainers.
- Out of v1: payments/fees, marketing site/CRM, built-in video.
- Client project: stakeholder approval gates matter more than market validation.

## Premises (agreed)
1. MVP = the Batch→Session→Assignment→Progress→Certificate loop for all 4 roles; billing,
   fees, marketing out of v1.
2. Mobile (Expo) for students + trainers; web admin for org admins, solo-trainer back-office,
   platform super-admin; corporate buyers get read-only web reports.
3. Multi-tenant from day 1: every tenant-owned row carries `tenant_id`, enforced by Supabase
   RLS. A solo trainer is a tenant of type `solo` with one member.
4. Live classes use external Zoom/Meet links in v1.
5. Distribution: TestFlight + Play internal testing for the pilot, then stores; web on Vercel.
6. Client workflow interview happens before building beyond the scaffold.

## Approaches Considered
### Approach A: Lean direct-to-Supabase
Clients call Supabase directly; logic in RLS + Postgres functions. Effort M, fastest.
Rejected: business rules (enrollment, grading, certificate eligibility) scatter across SQL and
become hard to test as roles multiply.

### Approach B: Monorepo + domain API layer (CHOSEN)
Turborepo monorepo; one typed API consumed by both apps; Supabase for DB/Auth/Storage with RLS
as defense in depth. Effort L (~2-3 weeks with CC).

### Approach C: Admin + PWA first
Web-only pilot, Expo later. Cheapest validation, but the client expects a mobile app.

### Auth & tenancy
- Supabase Auth (email OTP / magic link + Google). JWT carries `user_id`; tenant context is
  resolved per request from `memberships`.
- A user can belong to multiple tenants (e.g. a trainer teaching for two institutes); both apps
  have a tenant switcher.
- API layer checks role permissions; RLS independently restricts rows to the caller's tenants.
- Super-admin impersonation writes to `audit_log`.

### Core data model (v1)
`tenants(id, type[org|solo], name, slug, plan)` ·
`profiles(user_id, full_name, phone, avatar)` ·
`memberships(tenant_id, user_id, role[owner|admin|trainer|student|corporate_viewer])` ·
`corporate_clients(tenant_id, name)` + `corporate_client_members` ·
`courses(tenant_id, title, description, modules jsonb)` ·
`batches(tenant_id, course_id, name, start_date, end_date, corporate_client_id?)` ·
`batch_trainers`, `enrollments(batch_id, student_id, status)` ·
`sessions(batch_id, starts_at, ends_at, meeting_url, topic)` ·
`attendance(session_id, student_id, status, marked_by)` ·
`materials(batch_id|session_id, title, storage_path|url)` ·
`assignments(batch_id, title, due_at, max_score)` ·
`submissions(assignment_id, student_id, storage_path, text, submitted_at, score, feedback, graded_by)` ·
`certificates(enrollment_id, issued_at, pdf_path, verification_code)` ·
`announcements(batch_id, body)` · `notifications(user_id, type, payload, read_at)` ·
`audit_log(tenant_id, actor_id, action, target, at)`

### Key flows
1. Admin creates course → batch → assigns trainer → invites students (CSV or link).
2. Student accepts invite in app → sees batch schedule; push reminder 15 min before session.
3. Trainer marks attendance from mobile (one tap per student, offline-tolerant queue).
4. Trainer posts assignment → students submit file/text → trainer grades on mobile or web.
5. Certificate eligibility rule per batch (e.g. ≥75% attendance + all assignments ≥ pass mark)
   → admin issues → PDF generated server-side with a public verification URL.
6. Corporate viewer sees their employees' progress, exports CSV.

### Edge cases to design for
Student enrolled in batches across two tenants; trainer removed mid-batch; late submissions;
re-grading; timezone of session vs device; deleted student with issued certificate
(certificates stay valid); large file uploads on poor mobile networks; push permission denied.

## Success Criteria
- One real pilot batch runs end-to-end on the platform with no WhatsApp/Sheets fallback.
- Trainer marks attendance for a 30-student batch in < 60 seconds on mobile.
- Student opens app → sees next session and join link in ≤ 2 taps.
- Zero cross-tenant data leaks (RLS test suite covers every table).
- Corporate viewer can export completion report in one click.

## The Assignment

to walk you through last week's training for one batch — screen-share their WhatsApp, Sheets,
Drive, whatever they use. Write down every place they copy-paste, chase someone, or lose track.
Bring that list back; it decides the order of the v1 build.
